Turn a vague request into a useful brief

Carlsson & Co. · As of November 2026

Learn one habit: describe the result, supply the facts, and decide how you will check the answer. This lesson uses the same structure for ChatGPT, Claude and Codex: task, context, output, boundaries, example, exercise and checklist.

ChatGPT: make a realistic afternoon plan

  • Task: Turn a short task list into a plan you can follow.
  • Context: You have 90 minutes and three tasks with known durations.
  • Output: A timed table and a short explanation of anything deferred.
  • Boundaries: Use the supplied durations; flag missing facts.

Weak prompt

Plan my afternoon.

Improved prompt

Help me plan 14:00–15:30. I need to edit a report (40 minutes), prepare meeting notes (20 minutes), and sort a folder (45 minutes). The report is due today; the other tasks can wait. Include a 10-minute break. Return a table with start, finish and task, then explain what must wait. Use only these facts. Do not shorten the estimates to make everything fit.

Worked example

An illustrative answer, written for this lesson rather than recorded from a model:

StartFinishTask
14:0014:40Edit report
14:4014:50Break
14:5015:10Prepare meeting notes
15:1015:30Unallocated time

The folder needs 45 minutes and does not fit in the remaining 20 minutes. Schedule it later. Do not assume it can be split without checking.

Exercise

Replace the task names and estimates with three low-stakes tasks of your own. Run the weak prompt, then the improved prompt. Compare the two answers using the checklist.

Checklist

Claude: turn rough notes into a clear handover

  • Task: Help a colleague understand the next action.
  • Context: Supply the notes and say who will read them.
  • Output: A short summary and an action table.
  • Boundaries: Keep uncertain ownership and dates visible.

Weak prompt

Make these notes better.

Improved prompt

Turn the notes below into a handover for a colleague joining the project. Write a two-sentence summary, followed by a table with action, owner and due date. Use plain English. Keep unknown details as “Not confirmed”; do not invent commitments. Notes: Draft reviewed. Lee will update the introduction by Friday. Charts still need checking. Next review date undecided.

Worked example

Illustrative answer:

The draft has been reviewed, and the introduction needs an update. Chart checks and the next review date remain open.

ActionOwnerDue date
Update introductionLeeFriday; calendar date not confirmed
Check chartsNot confirmedNot confirmed
Confirm next review dateNot confirmedNot confirmed

Exercise

Write four fictional project notes, including one missing owner. Compare the weak and improved prompts. Follow up with: “Show which details need confirmation before I share this.”

Checklist

Codex: describe a small code change with a check

  • Task: Correct a function in a disposable practice project.
  • Context: Provide the file, the observed behavior and the intended result.
  • Output: A small change with verification evidence.
  • Boundaries: Limit the files and actions allowed.

Weak prompt

Fix my total function.

Improved prompt

In this disposable practice project, inspect totals.py. Its total_minutes(values) function currently returns len(values). It should return the sum of a list of non-negative integer durations, and return 0 for an empty list. Keep the function name and change only totals.py. Check [20, 40, 10] returns 70 and [] returns 0. Report the change, the checks you ran and their results. If you cannot run a check, say why. Do not install dependencies, commit, push or deploy.

Worked example

Practice input:

def total_minutes(values):
    return len(values)

An illustrative correction is return sum(values). An acceptable report includes the changed file and actual results for both checks. A plausible-looking patch alone does not demonstrate that the checks ran.

Exercise

Create that file in a disposable project you control. Compare the weak prompt and improved prompt, restoring the initial function between attempts. Review the diff and verify both outputs yourself.

Checklist

Reuse the structure

Help me [task]. Here are [facts]. Return [format]. Respect [boundaries]. Check [success criteria].

Review the answer and ask for one specific revision.
