Keep known facts apart from open questions

Carlsson & Co. · As of November 2026

A polished answer can make an uncertain detail look settled. Learn to supply a small fact record, name the gaps and ask the assistant to show which fact supports each statement. Review that record yourself before relying on the result.

ChatGPT: prepare an event note without filling gaps

  • Task: Prepare a short internal event note.
  • Context: Two facts are confirmed; the room is not.
  • Output: A fact table and one question to resolve the gap.
  • Boundaries: Do not turn an unknown into a likely answer.

Weak prompt

Write the details for our reading session. It is Tuesday at 15:00. Where should people go?

Improved prompt

Prepare an internal planning note using only this record. F1: The reading session is on Tuesday. F2: It starts at 15:00. Unknown: the room has not been selected. Return a table with Detail, Value and Source. Cite F1 or F2 where applicable and mark the room “Not confirmed”. Then give one question for the organiser. Do not infer a room or a calendar date from the weekday.

Worked example

Illustrative answer:

DetailValueSource
DayTuesdayF1
Start15:00F2
RoomNot confirmedUnknown in supplied record

Question for the organiser: Which room should attendees use?

Exercise

Add a fictional note saying “Room B suggested”. Ask for a revision that preserves the distinction between a suggestion and a confirmed booking.

Checklist

Claude: handle conflicting notes

  • Task: Summarise a project review time.
  • Context: Two notes disagree and neither is marked as superseded.
  • Output: The conflict and a focused confirmation question.
  • Boundaries: Do not choose a source merely because it appears last.

Weak prompt

When is the review? Note A says Thursday at 10:00. Note B says Thursday at 11:00.

Improved prompt

<notes>A: Review Thursday at 10:00. B: Review Thursday at 11:00. Neither note has a timestamp or approval status.</notes> Prepare an internal summary using only these notes. Show the agreed day and the conflicting times with their source letters. End with one question that would resolve the conflict. Do not choose a time or assume the second note is newer; we need confirmation before inviting anyone.

Worked example

Illustrative answer:

DetailStatusEvidence
DayThursday in both notesA and B
TimeNot confirmed: 10:00 or 11:00A: 10:00; B: 11:00

Which review time is confirmed: Thursday at 10:00 or Thursday at 11:00?

Exercise

Add a third note with a different time but no approval status. Check that the assistant lists the new conflict without treating repetition or order as authority.

Checklist

Codex: inspect an unspecified edge case

  • Task: Identify a missing behavior decision before editing code.
  • Context: A tiny function has defined behavior for non-empty lists only.
  • Output: An inspection report and a question about empty input.
  • Boundaries: Do not silently choose a default or modify files.

Weak prompt

Make average_minutes work for every input.

Improved prompt

In a disposable practice project, inspect stats.py without changing files. It contains average_minutes(values), shown below. Confirmed requirement: for a non-empty list of non-negative integers, return the arithmetic mean. Unknown: what should happen for an empty list. Check [10, 20] gives 15. Describe the current empty-list behavior and ask one question about the desired behavior. Do not choose a default, edit files, install dependencies, commit, push or deploy. Report which checks you actually ran.

Worked example

Illustrative practice input:

def average_minutes(values):
    return sum(values) / len(values)

For [10, 20], the expression gives 15.0. For [], it divides zero by zero and raises ZeroDivisionError. A useful question is: “Should empty input return a value, or raise a deliberate error?” Neither behavior is authorised by the supplied requirement.

Exercise

Create the practice file, try the inspection prompt and confirm both behaviors yourself. Then explicitly decide what empty input should mean before requesting a change.

Checklist

Reuse the structure

Confirmed facts: [labelled record]. Unknown or conflicting: [gaps]. Use only this record. Return [format] with the source for each claim. Keep gaps visible and ask [focused question].

A request to flag uncertainty helps you inspect the answer. It does not replace checking the facts and sources yourself.
